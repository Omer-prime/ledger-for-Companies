Resource mutations require the exact configured browser origin. The standalone ledger page now checks the same session as the admin layout. The old environment-based superadmin login was removed. The app no longer reads `ADMIN_EMAIL` or `ADMIN_PASSWORD`. Runtime secrets are the Mongo URI and its credentials. Branding variables prefixed with `NEXT_PUBLIC_` are client-visible. Some client master-data pages log response errors and unhandled database errors still need a consistent, redacted server logging policy. Neither password field is selected in the members API response.

## Incident and migration requirements

1. Isolate affected machines and build runners, preserve logs and artifacts, and assess process access and outbound activity. Revoke or rotate credentials reachable by the affected process as indicated by incident scope, including MongoDB passwords, GitHub tokens, SSH/deployment keys, service integrations and any legacy admin password. Reset exposed or reused user passwords. Static evidence establishes a potential exposure, with no confirmed exfiltration.
2. Take and verify a restricted backup. In an isolated restore, inventory account IDs and normalized emails and independently confirm user roles. The old user endpoint could create privileged accounts, so do not use its role values as the sole approval source. Lock unknown users and resolve email collisions before enabling login.
3. Set `APP_ORIGIN` to the exact HTTPS origin, with no trailing slash. Configure `MONGODB_URI` and `MONGODB_DATABASE` explicitly. In the rehearsal, use a dedicated disposable database and credentials incapable of accessing production. The prior application selected `ledger_app` regardless of the URI database.
4. Provision or reset users through a trusted offline operator path. Generate a fresh password for each approved user, hash it with `hashPassword` in `src/lib/password.ts`, and update by verified user ID using one Mongo update with `$set: { passwordHash, role, disabled: false }` and `$unset: { password: "" }`. Set a verified normalized email for each account. An approved superadmin must be created through this operator path, with the same password policy, a unique email and the confirmed role. Deliver temporary credentials out of band. Existing plaintext values never authenticate and must not be copied or hashed in place. Clear plaintext fields for disabled accounts as well, and restrict historical backups containing credentials.
5. Create TTL indexes on `expiresAt` with `expireAfterSeconds: 0` in `auth_sessions` and `auth_attempts`. Verify the unique users email index. Sessions expire in queries regardless of TTL cleanup. Clear any pre-cutover session rows and verify a password reset invalidates existing sessions. Exercise per-account and global login limits under representative load. The global bucket can be exhausted by abusive traffic and should be paired with an ingress limit.
6. Preserve transaction, account and movement IDs at cutover. Reconcile orphaned IDs, missing dates, amounts and duplicate records in a read-only dry run. Design reversal entries with a unique original-event reference, an idempotency key, actor, timestamp and reason. Post the compensating stock and balanced journal together in a Mongo transaction where applicable. Keep legacy single-entry rows available for historical statements and reconcile opening balances without double-counting. Reversal posting is pending.
